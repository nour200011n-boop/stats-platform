# سجلات المراجعين — المنصة (Web Platform)

منصة ويب لإدارة سجلات المراجعين للصيدليات، مبنية بـ HTML/CSS/JavaScript
عادي (بدون إطار عمل أو خطوة بناء Build)، ومتصلة بـ Firebase (Auth،
Firestore، Storage).

## الملفات
| الملف | الوظيفة |
|---|---|
| `index.html` | تسجيل الدخول / إنشاء حساب |
| `unlock.html` | إدخال رمز فتح التطبيق + إنشاء ملف الصيدلية |
| `app.html` | التطبيق الرئيسي: سجلات المراجعين، الإعدادات، حالة الاشتراك |
| `admin.html` | لوحة المالك (Super Admin): الإحصائيات، الصيدليات، الخطط ورموز التفعيل، الميزات، رموز الفتح، الإعلانات |
| `firebase-config.js` | إعداد Firebase — **يجب تعديله ببيانات مشروعك قبل التشغيل** |
| `shared.js` | أدوات مشتركة: الثيم، حراسة الدخول، تنسيق التواريخ |
| `platform.js` | منطق الأعمال: الميزات الديناميكية، الإعلانات، تفعيل الاشتراك |
| `styles.css` | التصميم المشترك لكل الصفحات |

## قبل التشغيل — إلزامي
1. **`firebase-config.js`**: استبدل القيم النائبة (`ضع_..._هنا`) ببيانات
   مشروعك الحقيقي (Firebase Console → ⚙️ Project settings → Your apps).
2. فعّل في Firebase Console: **Authentication** (Email/Password)،
   **Firestore Database**، **Storage**.
3. انشر ملف قواعد الأمان الموجود في حزمة Flutter المُسلَّمة سابقاً
   (`firestore.rules`) عبر:
   ```
   firebase deploy --only firestore:rules
   ```

## التشغيل محلياً
لا تفتح الملفات مباشرة بصيغة `file://` — بعض واجهات Firebase (خصوصاً
Auth) تتصرف بشكل غير موثوق على هذا البروتوكول. شغّل خادماً محلياً بسيطاً
من داخل مجلد `web_platform`:
```
python3 -m http.server 8000
```
ثم افتح `http://localhost:8000` في المتصفح. أو استخدم إضافة "Live
Server" في VS Code.

## النشر الفعلي (اختياري لاحقاً)
هذه ملفات ثابتة (Static) يمكن استضافتها على أي منصة: **Firebase
Hosting**، Netlify، Vercel، GitHub Pages، إلخ. لا تحتاج أي خطوة بناء
(Build Step) — ما تراه هو ما يُرفع تماماً كما هو.

## قيود معروفة — قبل أي إطلاق فعلي بمشتركين حقيقيين
- منطق تفعيل الاشتراك (`activateSubscriptionCode` في `platform.js`)
  يعمل حالياً من طرف العميل مباشرة لتسريع بناء أول نسخة تعمل. قبل
  إطلاق حقيقي، انقله إلى Cloud Function (نفس المنطق تقريباً، بتبديل
  Firestore SDK بحزمة Admin). التفاصيل الكاملة في README الخاص بحزمة
  Flutter.
- لم يُختبر هذا الكود فعلياً على مشروع Firebase حي بعد — تحقق جيداً من
  كل مسار (تسجيل، فتح، إنشاء صيدلية، إضافة مراجع، رفع صورة، تفعيل رمز)
  قبل الاعتماد عليه.
- بعض الاستعلامات (مثل `.orderBy` مع `.where`) قد تطلب من Firestore
  إنشاء فهرس مركّب (Composite Index) عند أول تشغيل — إن ظهر خطأ كهذا في
  الـ Console، اضغط الرابط الذي يوفّره Firebase تلقائياً لإنشاء الفهرس.
